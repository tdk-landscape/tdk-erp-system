# TDK Enterprise ERP System - Demo Walkthrough Guide

## Overview

This guide provides a step-by-step playbook for demonstrating the TDK Enterprise ERP System. The demo is designed to be completed in 3-5 minutes and showcases how 100 microservices can be orchestrated without manual configuration.

---

## Prerequisites Check (30 seconds)

Before starting the demo, verify:

```bash
# Check Docker is running
docker ps

# Check Tilt is installed
tilt version

# Check Bun is installed
bun --version

# Check TDK CLI is available
tdk --version
```

If any prerequisite is missing, pause and install it before proceeding.

## Demo Script: The 3-Minute Walkthrough

### Part 1: Introduction (30 seconds)

**Narrative:** "Today I'm going to show you how we can deploy a complete enterprise ERP system with 100 microservices across 7 business domains in just a few commands."

**Actions:**
1. Show the repository structure
2. Highlight the key files: `Tiltfile`, `TILT_SERVICE_DEFAULTS.star`, `TILT_TECH_STACK.star`
3. Mention the 7 domain folders in `services/`

**Key Points:**
- Each service has a simple `service.json` manifest
- TDK CLI generates all infrastructure automatically
- No manual Docker, Kubernetes, or environment configuration needed

## Common Demo Questions & Answers

### Q: How does this compare to SAP/Oracle?
**A:** "Unlike monolithic ERPs, we use microservices which means faster deployment, independent scaling, and no vendor lock-in. Implementation is 60-80% cheaper and 5-10x faster."

### Q: What about data consistency across services?
**A:** "We use event-driven architecture with NATS messaging for eventual consistency. Each service owns its data, and we have dedicated services for data governance and synchronization."

### Q: How do you handle upgrades?
**A:** "Since services are independent, we upgrade one at a time with rolling updates. No big bang upgrades, no system-wide downtime, and instant rollback capability."

### Q: What about security and compliance?
**A:** "We have dedicated compliance services for each domain (tax-compliance-api, audit-trail-api, compliance-api). Security is built-in with OAuth2, role-based access, and audit logging."

### Q: Can we customize this for our business?
**A:** "Absolutely. The service.json manifests are completely customizable. You can add, remove, or modify services based on your specific needs. The architecture is designed for extensibility."

### Q: What's the learning curve for our team?
**A:** "Since we use standard JavaScript/TypeScript, React, and modern tooling, most developers are already familiar. The TDK CLI handles the complex infrastructure parts, so your team focuses on business logic."

## Troubleshooting Common Demo Issues

### Port Conflicts
**Issue:** Services fail to start due to port conflicts
**Solution:** Check `tdk status` for port allocation, modify `TILT_SERVICE_DEFAULTS.star` if needed

### Docker Issues
**Issue:** Docker daemon not running or permissions issues
**Solution:** Start Docker daemon, ensure user has Docker permissions

### TDK CLI Not Found
**Issue:** `tdk` command not available
**Solution:** Install TDK CLI per documentation at https://github.com/tdk-landscape/tdk-cli

### Services Not Starting
**Issue:** Services remain in red/yellow state in Tilt UI
**Solution:** Check service logs in Tilt UI, verify health check paths in service.json

### Memory Issues
**Issue:** System runs out of memory with 100 services
**Solution:** Reduce domain count for demo, adjust memory limits in `TILT_SERVICE_DEFAULTS.star`
